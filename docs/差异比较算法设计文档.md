# DB-Comparator 表数据差异比较算法设计文档

> **项目名称**：db-comparator  
> **版本**：2025.10.1  
> **编写日期**：2026-09-16  
> **文档范围**：差异比较（Primary 模式）的核心算法设计

---

## 1. 概述

### 1.1 项目定位

DB-Comparator 是一个异构数据库表级数据差异比较工具，支持 Oracle、MySQL、GaussDB 三种数据源之间的跨库比对操作。系统采用 Spring Boot 后端 + WebSocket 实时通信架构，前端通过 WebSocket 接收比较进度与结果文件。

### 1.2 核心能力

| 能力 | 说明 |
|---|---|
| **差异比较** | 比较源端与目标端表的数据差异，输出仅存于源端/目标端的行，生成 Excel 差异报告 |
| **实时反馈** | 通过 WebSocket 实时推送比较进度与差异结果文件 |

### 1.3 支持的数据源

| 数据源 | JDBC 驱动 | 连接串模板 |
|---|---|---|
| MySQL | `com.mysql.cj.jdbc.Driver` | `jdbc:mysql://{host}:{port}/{db}?useSSL=false&serverTimezone=UTC` |
| Oracle | `oracle.jdbc.OracleDriver` | `jdbc:oracle:thin:@{host}:{port}:{sid}` |
| GaussDB | `org.postgresql.Driver` | `jdbc:postgresql://{host}:{port}/{db}?useSSL=false` |

## 3. 差异比较算法（Primary 模式）

### 3.1 算法总体流程

```
┌──────────────────────────────────────────────────────────────────────────┐
│                         差异比较完整流程                                   │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  1. 预检阶段 (PrimaryController)                                         │
│     ├─ 获取源端/目标端列元数据                                            │
│     ├─ 校验字段数量一致                                                   │
│     ├─ 校验字段名、类型兼容性                                              │
│     ├─ 排除含 blob/clob/raw 类型的表                                      │
│     └─ 构造双端 SELECT ... ORDER BY 全部列 SQL                            │
│                                                                          │
│  2. 查询阶段 (PrimaryService)                                            │
│     ├─ 建立源端/目标端数据库连接                                           │
│     ├─ 设置 fetchSize=2000（流式读取）                                    │
│     ├─ GaussDB 特殊处理：set session_timeout=36000                       │
│     └─ 执行双端查询获得 ResultSet                                         │
│                                                                          │
│  3. 遍历比较阶段 (PrimaryListenerRegistry + PrimaryListener)              │
│     ├─ 阶段1：双端同步推进 (rsS.next() && rsT.next())                    │
│     ├─ 阶段2：源端剩余行 (rsS.next())                                    │
│     ├─ 阶段3：目标端剩余行 (rsT.next())                                  │
│     └─ 每1000行执行一次批量差集计算                                       │
│                                                                          │
│  4. 结果导出阶段 (PrimaryListener)                                       │
│     ├─ 差异累积 >10000 行时触发溢出导出                                   │
│     ├─ 全量遍历结束后执行最终导出                                          │
│     └─ 通过 WebSocket 以二进制帧发送 Excel 文件                           │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3.2 预检阶段

#### 3.2.1 表结构一致性校验

系统在执行数据比较前，必须先通过表结构校验，拒绝结构不一致的表进行比较。

**校验规则**（`ColumnInfo.equals()`）：

| 校验项 | 规则 | 不一致时的行为 |
|---|---|---|
| 字段数量 | `sizeS == sizeT` | 抛出异常，拒绝比对 |
| 字段名称 | 逐列比较 `columnName`，按列序对齐 | 抛出异常，提示具体不一致字段名 |
| 字段类型 | 通过 `toJavaType()` 映射为 Java 类型后比较 | 抛出异常，提示具体类型不一致 |
| 数值类型兼容 | `number` 与 `int/double/numeric/decimal` 互相兼容 | 视为一致 |
| 字段精度 | 数值类型通过 `compareNumber()` 包容处理 | 视为一致 |

**类型兼容性矩阵**：

```
          number  int  double  numeric  decimal  char  date  blob  clob  raw
number      ✓      ✓      ✓       ✓        ✓      ✗     ✗     ✗     ✗    ✗
int         ✓      ✓      ✓       ✓        ✓      ✗     ✗     ✗     ✗    ✗
double      ✓      ✓      ✓       ✓        ✓      ✗     ✗     ✗     ✗    ✗
numeric     ✓      ✓      ✓       ✓        ✓      ✗     ✗     ✗     ✗    ✗
decimal     ✓      ✓      ✓       ✓        ✓      ✗     ✗     ✗     ✗    ✗
char        ✗      ✗      ✗       ✗        ✗      ✓     ✗     ✗     ✗    ✗
date        ✗      ✗      ✗       ✗        ✗      ✗     ✓     ✗     ✗    ✗
blob        —      —      —       —        —      —     —    拒绝   —    —
clob        —      —      —       —        —      —     —     —    拒绝  —
raw         —      —      —       —        —      —     —     —     —    拒绝
```

> ✓ = 兼容，✗ = 不兼容，— = 不适用（已提前拒绝）

#### 3.2.2 SQL 构造

```java
// SqlUtil.sql() 构造两条排序查询
selectSqlS = "SELECT * FROM {tableNameS} {where} ORDER BY col1, col2, ..., colN"
selectSqlT = "SELECT * FROM {tableNameT} {where} ORDER BY col1, col2, ..., colN"
```

**设计要点**：
- ORDER BY 使用**全部列名**，确保两端结果集按相同的列序排列
- `{where}` 由前端传入，支持指定过滤条件缩小比较范围
- 列名列表从源端表元数据获取，假设两端表结构一致

### 3.3 查询阶段

#### 3.3.1 连接与查询建立

```java
// PrimaryService.comparePrimary() 核心逻辑
connectionS.setAutoCommit(false);
statementS = connectionS.createStatement(
    ResultSet.TYPE_FORWARD_ONLY,    // 仅向前游标
    ResultSet.CONCUR_READ_ONLY      // 只读并发
);
statementS.setFetchSize(2000);      // 每次从数据库拉取2000行
```

**流式读取设计**：
- `setAutoCommit(false)` + `setFetchSize(2000)`：MySQL 驱动在此配置下采用流式 ResultSet，避免全量加载到内存
- `TYPE_FORWARD_ONLY` + `CONCUR_READ_ONLY`：仅向前、只读模式，配合流式读取
- GaussDB 特殊处理：`set session_timeout=36000`，防止长查询超时断连

#### 3.3.2 保活机制

```java
// 每10000行执行一次 ping 查询，保持数据库连接活跃
if (currentRow % 10000 == 0) {
    pingStatement.execute();       // 源端: SELECT 1 / SELECT 1 FROM DUAL
    preparedStatement.execute();   // 目标端: SELECT 1 / SELECT 1 FROM DUAL
}
```

| 数据源 | Ping SQL |
|---|---|
| MySQL | `SELECT 1` |
| GaussDB | `SELECT 1` |
| Oracle | `SELECT 1 FROM DUAL` |

### 3.4 行指纹生成算法

行指纹是差异比较的核心数据结构，用于唯一标识一行数据。

#### 3.4.1 算法描述

```
输入: ResultSet 当前行 + 列元数据列表
输出: 行指纹字符串

算法:
  初始化 pkBuilder (StringBuilder)
  FOR i = 0 TO columnInfos.size() - 1 DO
    IF i > 0 THEN pkBuilder.append("|")
    
    ColumnInfo info = columnInfos[i]
    
    CASE info.dataType:
      包含 "char":
        value = resultSet.getObject(i+1)
        IF value != NULL THEN pkBuilder.append(value)
        
      包含 "num":  
        decimal = resultSet.getBigDecimal(i+1)
        IF decimal != NULL THEN
          scale = info.dataScale
          IF scale >= 0 THEN decimal = decimal.setScale(scale, RoundingMode.DOWN)
          pkBuilder.append(decimal.toPlainString())   // 非科学计数法
          
      value == NULL:
        /* 不拼接任何内容 */
        
      其他:
        pkBuilder.append(resultSet.getObject(i+1))
        
  RETURN pkBuilder.toString()
```

#### 3.4.2 指纹拼接示例

| 行数据 (col1, col2, col3) | 列类型 | 指纹输出 |
|---|---|---|
| `("Alice", 100, 3.14)` | (varchar, number, number) | `Alice\|100\|3.14` |
| `("Bob", NULL, 99)` | (varchar, number, number) | `Bob\|\|99` |
| `(NULL, NULL, NULL)` | (varchar, number, number) | `\|\|` |
| `("X", 1E+5, 0)` | (varchar, number, number) | `X\|100000\|0` |

#### 3.4.3 数值类型处理规则

```
                    getBigDecimal()
                          │
                    ┌─────▼──────┐
                    │  decimal   │
                    └─────┬──────┘
                          │
                ┌─────────▼─────────┐
                │  scale >= 0 ?     │
                └───┬──────────┬────┘
                   Yes         No
                    │           │
           ┌────────▼─────┐    │
           │ setScale(     │    │
           │   scale,      │    │
           │   DOWN)       │    │
           └───────┬──────┘    │
                   │           │
           ┌───────▼───────────▼───────┐
           │  toPlainString()          │
           │  (避免科学计数法)          │
           └───────────────────────────┘
```

- `RoundingMode.DOWN`（向零截断）：正数向下取整，负数向零取整
  - 例：`1.567` scale=2 → `1.56`；`-1.567` scale=2 → `-1.56`
- `toPlainString()`：避免 `1E+5` 与 `100000` 被判定为不同

### 3.5 三阶段遍历与差集计算

#### 3.5.1 遍历策略

```
ResultSetS (源端):   ──► A  B  C  D  E  F  G  ──────►
ResultSetT (目标端): ──► A  B  C  D  E  X  Y  Z  ──►

阶段1: 同步推进      │A│B│C│D│E│
                     ↓ ↓ ↓ ↓ ↓
                     F G (源端余)    X Y (目标端余)

阶段2: 源端剩余           │F│G│
阶段3: 目标端剩余                    │X│Y│Z│
```

**PrimaryListenerRegistry.addRegistry() 伪代码**：

```
WHILE resultSetS.next() AND resultSetT.next() DO
    listener.invoke(resultSetS, resultSetT)     // 阶段1: 双端同步推进
END WHILE

WHILE resultSetS.next() DO
    listener.invokeS(resultSetS)                // 阶段2: 源端剩余
END WHILE

WHILE resultSetT.next() DO
    listener.invokeT(resultSetT)                // 阶段3: 目标端剩余
END WHILE

listener.doAfterAllAnalysed()                   // 阶段4: 收尾
```

#### 3.5.2 集合差集算法

系统使用 `HashSet` 的 `removeAll()` 操作计算集合差集。

**数据结构**：

```
┌─────────────────────────────────────────────────┐
│  PrimaryListener 内存结构                        │
│                                                  │
│  setS: HashSet<String>    ← 本批次源端指纹        │
│  setT: HashSet<String>    ← 本批次目标端指纹      │
│                                                  │
│  map: HashMap<String, Set<String>>               │
│    "s" → 累积的仅存于源端的指纹集合               │
│    "t" → 累积的仅存于目标端的指纹集合             │
└─────────────────────────────────────────────────┘
```

**差集计算过程** (`processBatchData()`)：

```
每处理 1000 行触发:

1. 合并本批次指纹到累积集合:
   s = map["s"] ∪ setS
   t = map["t"] ∪ setT

2. 计算差集:
   totalT = t 的备份
   t = t - s        // 仅存于目标端 = T \ S
   s = s - totalT   // 仅存于源端 = S \ T

3. 存回:
   map["s"] = s
   map["t"] = t

4. 清空本批次缓冲:
   setS.clear()
   setT.clear()
```

**数学表达**：

$$
\text{仅存于源端} = S_{cumulative} \cup S_{batch} \setminus (T_{cumulative} \cup T_{batch})
$$

$$
\text{仅存于目标端} = T_{cumulative} \cup T_{batch} \setminus (S_{cumulative} \cup S_{batch})
$$

#### 3.5.3 差集收敛过程示例

以 5 行一批为例，展示差集在多批次中如何逐步收敛：

```
批次1: 源端 = {A, B, C, D, E}    目标端 = {A, B, C, F, G}
  ──► 差集: 仅源端 = {D, E}       仅目标端 = {F, G}

批次2: 源端 = {F, G, H}           目标端 = {D, E, I}
  合并: 源端累积 = {D,E} ∪ {F,G,H} = {D,E,F,G,H}
        目标端累积 = {F,G} ∪ {D,E,I} = {D,E,F,G,I}
  ──► 差集: 仅源端 = {H}          仅目标端 = {I}

批次3: 源端 = {I}                 目标端 = {H}
  合并: 源端累积 = {H} ∪ {I} = {H,I}
        目标端累积 = {I} ∪ {H} = {H,I}
  ──► 差集: 仅源端 = {}           仅目标端 = {}

结果: 无差异 ✓
```

## 4. 关键设计决策

### 4.1 全列指纹 vs 主键指纹

| 方案 | 本项目选择 | 优劣分析 |
|---|---|---|
| 主键指纹比较 | ✗ 未采用 | 只能判断行是否存在，无法检测同主键数据变更 |
| 全列指纹比较 | ✓ 已采用 | 可检测数据差异，但无法定位具体差异列 |
| 逐字段比较 | ✗ 未采用 | 可定位具体差异列，但计算量大、实现复杂 |

**设计理由**：本工具的目标是发现"哪些行有差异"，而非"哪些字段有差异"，全列指纹在计算效率和检测能力之间取得了平衡。

### 4.2 集合差集 vs 逐行对齐

| 方案 | 本项目选择 | 优劣分析 |
|---|---|---|
| 排序后逐行对齐比较 | ✗ 未采用 | 依赖排序稳定性，对齐逻辑复杂，无法处理行数不一致 |
| HashSet 差集 | ✓ 已采用 | 不依赖行顺序，天然支持行数不一致，实现简洁 |
| HashMap 差集（支持更新检测） | ✗ 未采用 | 可检测同键不同值，但需定义行键 |

**设计理由**：HashSet 差集算法不依赖行顺序，对排序不稳定具有天然容错能力，且实现简洁。

### 4.3 分批溢出 vs 全量内存

| 方案 | 本项目选择 | 优劣分析 |
|---|---|---|
| 全量加载后计算差集 | ✗ 未采用 | 大表 OOM 风险高 |
| 分批溢出导出 | ✓ 已采用 | 内存可控，差异多时自动分文件输出 |

**设计理由**：数据库比较场景中表数据量可能非常大，分批溢出机制确保内存占用始终可控。

## 5. 性能设计

### 5.1 性能参数一览

| 参数 | 值 | 作用 |
|---|---|---|
| `fetchSize` | 2000 | JDBC 每次从数据库拉取的行数 |
| `batchSize` | 1000 | 每处理多少行触发一次差集计算 |
| `pingStatement` 间隔 | 10000 行 | 保活探测的行间隔 |
| `progressReport` 间隔 | 1000 行 | WebSocket 进度推送的行间隔 |
| 溢出导出阈值 | 差异 > 10000 行 | 触发 Excel 导出并清空内存 |

### 5.2 时间复杂度分析

| 操作 | 时间复杂度 | 说明 |
|---|---|---|
| 行指纹生成 | O(C) | C = 列数，逐列拼接 |
| 指纹加入 HashSet | O(1) 均摊 | 依赖哈希函数质量 |
| 差集计算 `removeAll` | O(min(\|S\|, \|T\|)) | 遍历较小集合查找较大集合 |
| 全量比较 | O(N) | N = max(源端行数, 目标端行数) |

### 5.3 空间复杂度分析

| 数据结构 | 空间复杂度 | 说明 |
|---|---|---|
| `setS` / `setT` | O(batchSize) | 最多 1000 个指纹字符串 |
| `map["s"]` / `map["t"]` | O(D) | D = 累积差异数，溢出后清零 |
| ResultSet 缓冲 | O(fetchSize) | 数据库驱动侧缓冲 |
| Excel 输出 | O(D_batch) | 单次导出的差异行 |

**峰值内存** ≈ O(batchSize + D + fetchSize)，其中 D 在溢出前最大为 10000。

## 6. 已知限制与风险

### 6.1 NULL 值指纹歧义

**问题描述**：`getCon()` 中 NULL 值不拼接任何字符，仅产生分隔符 `|`。

**影响**：
- `("A", NULL, "B")` → 指纹 `A||B`
- `("A", "", "B")` → 指纹 `A||B`（空字符串同样拼接为空）

两端数据若一端为 NULL、另一端为空字符串，将产生**相同指纹**，导致差异漏检。

**建议修复**：NULL 值使用特殊标记替代，如 `A|<NULL>|B`。

### 6.2 排序不稳定性风险

**问题描述**：`ORDER BY 全部列` 在存在完全重复行时，排序结果不稳定（数据库不保证重复行的相对顺序）。

**影响**：阶段1的双端同步推进 `while (rsS.next() && rsT.next())` 将两端行视为一一对应，若排序不稳定导致行错位，则后续行全部配对错误，产生大量假阳性差异。

**当前缓解**：HashSet 差集算法本身不依赖行顺序，错位仅影响阶段1中的临时集合 `setS`/`setT`，最终差集结果通过多次合并仍可收敛到正确结果。但阶段1的存在在逻辑上是冗余的——阶段2和阶段3已经覆盖了所有行的处理。

### 6.3 数值截断方向

**问题描述**：`RoundingMode.DOWN`（向零截断）对负数的处理可能不符合预期。

**影响**：
- `-1.567` scale=2 → `-1.56`（向零截断）
- 若期望四舍五入：`-1.57`

如果两端数据库对负数的存储精度处理不同，可能导致误判。

### 6.4 大对象类型不可用

**问题描述**：含 `blob`、`clob`、`raw` 类型的表直接拒绝比较。

**影响**：含有大对象列的业务表无法使用本工具。

### 6.5 列顺序敏感性

**问题描述**：表结构校验和指纹生成均按列的物理顺序（`ResultSetMetaData` 返回顺序）对齐。

**影响**：若两端表列名相同但物理顺序不同（如源端 `[A, B]`、目标端 `[B, A]`），将导致校验失败或指纹错位。

## 7. 改进建议

### 7.1 短期改进（低风险）

| 编号 | 改进项 | 说明 |
|---|---|---|
| S1 | NULL 值指纹标记 | 将 NULL 替换为特殊标记如 `\0N`，避免与空字符串混淆 |
| S2 | 增加列名排序对齐 | 表结构校验时按列名排序后再比较，消除列顺序敏感性 |
| S3 | 差异结果增加列级定位 | 在指纹基础上增加逐字段哈希，可定位到具体差异列 |

### 7.2 中期改进（中等风险）

| 编号 | 改进项 | 说明 |
|---|---|---|
| M1 | 改为纯集合差集模式 | 移除阶段1的双端同步推进，源端/目标端分别独立遍历，全部行加入 Set 后做差集，逻辑更简洁 |
| M2 | 引入行级哈希而非全列拼接 | 使用 MD5/SHA1 对行数据生成定长哈希，减少内存占用和字符串比较开销 |
| M3 | 支持大对象类型 | 对 blob/clob/raw 采用流式哈希（如分块 MD5），而非直接拼接 |
| M4 | 增量比较模式 | 基于时间戳或自增ID，仅比较增量数据，减少全表扫描 |

### 7.3 长期改进（高投入）

| 编号 | 改进项 | 说明 |
|---|---|---|
| L1 | 分布式比较 | 引入分片机制，按主键范围分区并行比较，提升大表比较速度 |
| L2 | Checksum 表级预筛 | 先执行 `BIT_XOR` / `CHECKSUM_AGG` 等表级校验和，若一致则跳过行级比较 |
| L3 | 支持更多数据源 | 扩展 PostgreSQL、SQL Server、DM 等数据源适配 |
